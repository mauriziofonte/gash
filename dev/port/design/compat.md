# Compatibility layer (shims)

Goal (PRD 5.2): for the whole 3.x line, every 2.x way of using Gash keeps
working, while `gash <command>` becomes the primary interface.

## 1. Generated, committed Bash

All Bash that 3.x ships is generated by `internal/compatgen` from the registry
and committed, so a checkout works with no build step:

| Path | Role |
|---|---|
| `gash.sh` | Entry point sourced by every `~/.gashrc` (interactive and headless) |
| `lib/compat/bootstrap.sh` | Binary resolution, first-run fetch, the call wrapper, the missing-binary envelope; sourced by every file below |
| `lib/core/output.sh`, `lib/core/validation.sh`, `lib/core/utils.sh`, `lib/core/config.sh` | The 4 core paths external harnesses source by path |
| `lib/modules/php.sh`, `lib/modules/node.sh`, `lib/modules/remote.sh` | The 3 module paths external harnesses source by path |
| `bash_completion` | Completion for every function and alias (static, from the registry) |
| `bin/gash` | POSIX `sh` launcher for direct use (`~/.gash/bin/gash llm_tree`): execs the binary of this checkout's `VERSION` |

CI regenerates them and fails on any difference (`gash __compat generate
--check`). shellcheck and shfmt keep running on them, and the Bash version
matrix (4.4, 5.0, 5.1, 5.3) keeps running the compat specs.

`.gashrc` (the template) is not changed: existing `~/.gashrc` files guard on
`[ -f "$__gash_home/gash.sh" ]` and `bash_completion`, which keep existing at
the root.

## 2. Binary resolution (no forks while sourcing)

`lib/compat/bootstrap.sh` computes the path once, with Bash string operations
only (`$OSTYPE` and `$HOSTTYPE` give os/arch; no `uname`):

1. `GASH_BIN` when set and executable (environment-only, new: tests and
   developer builds).
2. `${XDG_DATA_HOME:-$HOME/.local/share}/gash/versions/<VERSION>/gash`, where
   `<VERSION>` is the checkout's `VERSION` file (already read into
   `GASH_VERSION`).

The binary lives outside the install directory on purpose: a file there that
is untracked in some version would block every later `gash_upgrade` (it
refuses a dirty `git status --porcelain`), including after a checkout back to
`v2.1.0`, whose `.gitignore` knows nothing of 3.x paths.

When the file is missing, `__gash_fetch` downloads it once (section 4 of
`upgrade.md`): at source time in an interactive shell (one stderr line on
success or failure). In headless mode it is not downloaded (3.4.2): each
call answers `binary_not_found`; with `GASH_AUTO_FETCH=1` the first call
downloads it (silent; a failure surfaces as the envelope of that call).
`GASH_AUTO_FETCH=0` turns both off; `install.sh` and `--repair` always
fetch. Concurrent fetches serialize on a `mkdir` lock in the versions
directory.

## 3. The call wrapper

Every delegated function is one line, generated:

```bash
llm_tree() { __gash_call llm_tree "$@"; }
```

`__gash_call` passes the caller's shell state that 2.x read as shell variables
and that a child process would otherwise not see, because callers set them
without exporting (`GASH_HEADLESS=1` is set non-exported by the known
harnesses):

* mode and output: `GASH_HEADLESS`, `NO_COLOR`, `GASH_NO_COLOR`, `GASH_DEBUG`,
  `GASH_TUI`, `COLUMNS`;
* locations: `GASH_DIR`, `GASH_ENV_FILE`, `HISTFILE` (history functions),
  `NVM_DIR` (node functions), `GASH_CHROME_ROOT` and `GASH_CHROME_LINK`
  (`chrome_headless_update`);
* shell state read by single functions: `__AI_LAST_EXIT` (the exit status
  the prompt hook saved, read by the `ai_*` functions), `GASH_AI_DEBUG`;
  the registry entry of each function lists the shell variables its 2.x
  code read, and the generated stub passes exactly those;
* every setting of `__GASH_SETTINGS_KNOWN` that the 2.x function would have
  read from the shell (the environment-wins rule), with a companion
  `GASH__SET` list naming the ones that are set, so "set to empty" and "unset"
  stay different, as in 2.x (`${!key+x}`);
* never `GASH_LLM_EXEC`, `GASH_LLM_EXEC_ALLOW`, `GASH_LLM_SANDBOX`: the binary
  reads those from the file only (MUST NOT 5), and ignores them in its own
  environment.

The binary inherits the caller's file descriptors, so its TTY tests answer
exactly what `[[ -t 1 ]]` answered inside the 2.x function (a pipe inside
`$(...)`, the terminal otherwise).

Return codes: the binary's exit status, unchanged. A missing binary that
cannot be fetched: the error envelope on stderr and status 1:

```json
{"error":"binary_not_found","details":"gash 3.0.0 for linux/amd64 is not installed and could not be downloaded","action":"STOP","recoverable":true,"hint":"Run: bash ~/.gash/install.sh --repair"}
```

`binary_not_found` is a new code (MATRIX row), the only one the compat layer
adds. Human-facing functions print the same as one `Error:` line plus a
`Hint:` line, following the 2.x stream policy.

## 4. What stays Bash, and why

Only what must act on the calling shell, plus presentation helpers that
external harnesses call under `set -euo pipefail` and that must never fail or
fork:

| Kind | Implemented in the generated Bash | Examples |
|---|---|---|
| Shell-mutating functions | The parent-shell effect in Bash, the computation in the binary | `mkdir_cd` (cd), `path_add` (PATH), `gash_unload`, `sudo_last` (reads `fc`), `gash_ssh_auto_unlock` (exports `SSH_AUTH_SOCK`/`SSH_AGENT_PID` that the binary prints, quoted), nvm lazy loading |
| Presentation primitives of `lib/core/output.sh` | Bash, byte-identical output, no forks, never non-zero where 2.x was not | color and glyph variables, `__gash_info`, `__gash_error`, `__gash_warning`, `__gash_success`, `__gash_note`, `__gash_hint`, `__gash_usage`, `__gash_kv`, `__gash_mark`, ... |
| Heavy presentation primitives | Delegated to the binary (`gash __compat output table ...`, rows on stdin); without a binary they degrade to plain tab-separated rows | `__gash_table`, `__gash_box`, `__gash_wrap`, `__gash_choose`, `__gash_download` |
| Config helpers of `lib/core/config.sh` | Delegated: `gash __compat env load` prints the parsed cache as quoted Bash assignments (`mvdan.cc/sh/v3/syntax` quoting), evaluated by the shim; secrets travel on the pipe only, never argv, environment or files | `__gash_load_env`, `__gash_get_db_url`, `__gash_parse_db_url`, `__gash_get_ssh_keys`, `__gash_apply_settings` |
| Validation helpers | Bash (they test the caller's environment: `command -v`, `-f`, `git rev-parse`) | `__gash_require_*` |

The full list, function by function with its decision, is in
`go-impl/PORT/MATRIX.md` (kind "compat function"). Every helper that 2.x
defined in the 7 paths keeps its name and signature, so callers keep working
whatever subset they use. Where a 2.x helper evaluated a user string as Bash
arithmetic (`__gash_require_args_min`, `__gash_bar`, `__gash_human_size` on
unvalidated input), the shim validates the integer first and returns the
error the function documents: a forced divergence with a LEDGER entry.

The load-time behavior of the 7 files is preserved: sourcing prints nothing,
never returns non-zero, does not depend on the binary being present and
leaves no `BASH_REMATCH` or other globals behind, under `set -euo pipefail`.

## 5. Headless and interactive `gash.sh`

```
gash.sh
  Bash >= 4.4 check (same message)
  [[ $- != *i* && $GASH_HEADLESS != 1 ]] → return 0
  GASH_DIR (same derivation), GASH_VERSION (read from VERSION, no exec)
  source lib/compat/bootstrap.sh
  static stubs for every public function, module short aliases (headless too)
  headless:    source the 4 core shims; return 0           (nothing printed, never non-zero)
  interactive: snapshot (PS1, PS2, HIST*, EDITOR, PATH, shopts, umask) unless one exists
               eval "$("$bin" init bash)"  → prompt, history, terminal, toolchains,
                                              alias packs, banner, SSH unlock
               ~/.bash_aliases, ~/.bash_local (top level, as 2.x)
               no binary → one stderr line; stubs stay defined and answer binary_not_found
```

`declare -F` lists every 2.x public function as a real shell function in both
modes; `$GASH_VERSION` is set in both; module short aliases are defined in
headless mode too (agent contract, even though non-interactive Bash does not
expand them).

Re-sourcing over a running 2.x session (`source ~/.gashrc` after
`gash_upgrade`, as 2.x suggests) is supported: the 2.x snapshot
(`__GASH_SNAPSHOT`) is kept as the pre-Gash state, 2.x functions and the 2.x
prompt hook are replaced, and `gash_unload` then restores the shell as it was
before 2.x loaded (variables, aliases, completion specs, shell options, traps,
umask and the user's exported `GASH_*` settings). What 2.x set without
recording the earlier value stays as 2.x's own `gash_unload` left it: its
module variables (`__AI_*`, `__LLM_*`, `__REMOTE_*`, `__SYSINFO_*`, many of
them read-only, which no unload can remove) and `LESSOPEN`, `LESSCLOSE`,
`LS_COLORS` (`LSCOLORS` on macOS) and an empty `PROMPT_COMMAND`. Proven by
`testdata/script/upgrade_2x_resource.txtar`.

## 6. Direct invocation

`gash <function> [args]` runs the same code with the same arguments, output
and exit status as the shell function (the function is a stub that calls it).
`gash <topic>` keeps showing the reference card, `gash migrate` the pointer to the
2.x route for 1.x installs (D-6). New: `gash init bash`, `gash update`, `gash version`, `gash hte
...`, hidden `gash __compat ...` and `gash __complete ...`. For agents that do
not source Gash, `~/.gash/bin/gash` is a stable path; `install.sh` offers to
link it into `~/.local/bin`.
